Background
Joveo helps employers and staffing firms hire faster by placing and optimising job ads across hundreds of publishers.
Every campaign starts with the same questions from a client: how competitive is this role in this location, what should we
pay, and which skills should the job description lead with.
Today a customer success manager answers these by hand: searching job boards, eyeballing salary ranges, and
pasting findings into a deck. It takes hours per role, the quality varies by person, and the answer is rarely backed by
traceable evidence.
AI agents can do this research loop well, but only if they know when to ask a human for clarification, when the data is good
enough, and when to stop. This assessment asks you to build exactly that: a Talent Market Scout Agent that takes a hiring
request, clarifies it with the user, gathers real job postings, and produces a structured market brief a CSM could hand to
a client.

What We Are Evaluating
This assessment evaluates your ability to:
Design a stateful, multi-step agent as an explicit graph in LangGraph, with clear state, nodes, and routing decisions
Build human-in-the-loop checkpoints where the agent pauses, asks the user for what it needs, and resumes correctly
Write reliable prompts and structured outputs for a production-style task
Integrate with a real-world data API and an LLM provider, and use tool calling so the model decides which tool to use
Handle large result sets, sparse or messy data, ambiguous inputs, and API failures without crashing
Explain your design decisions clearly in writing and live in the interview

1
STEP 1
Intake the request
Accept a hiring request with: role or job title, location, and any optional details the user gives (seniority, employment
type, remote/hybrid, currency, the client’s purpose). Store everything in a typed graph state.
2
STEP 2 · HUMAN-IN-THE-LOOP
Clarify with the user
Before doing any research, the agent checks whether the request is specific enough. If it is not, the graph must pause at a
node, show the user 1–3 targeted questions, wait for answers, and then resume from the same point with the answers
added to state.
Examples: “Engineer” is ambiguous (software, civil, mechanical?). “Texas” may mean the whole state or one metro area.
“Senior” may mean 5+ years or a specific level. If the request is already clear, the agent should skip this pause rather than
ask questions for the sake of it.
3
STEP 3
Plan the search
The agent drafts a search plan: title variants and synonyms, location scope and radius, date range, and the target number
of postings. The plan is stored in state so later steps and the write-up can refer to it.

4
STEP 4
Gather postings
Use tool calling to fetch real job postings from a public jobs API, then deduplicate them. After each fetch, the agent
decides whether the sample is good enough:
Enough relevant postings → continue to analysis
Too few or too noisy → broaden or refine the search and fetch again, within a fixed limit of attempts
Still too few after the limit → pause and ask the user whether to broaden further or continue with a weak sample
5
STEP 5
Analyse the market
Pass the postings to an LLM and analyse them across the dimensions below. For large result sets, split postings into
batches, analyse batches in parallel, and merge the results.
Dimension
What to extract or compute
Demand & volume
Number of relevant active postings, how recent they are, and any trend visible in
posting dates
Compensation
Salary range (median, middle 50%), share of postings that disclose pay, normalised
to one currency and period
Skills & requirements
Most-requested skills (normalised so “Postgres” and “PostgreSQL” count once),
must-have vs nice-to-have, typical years of experience
Competition
Top hiring employers, and the split between direct employers and staffing agencies
Titles & seniority
The title variants employers actually use, and the seniority mix
6
STEP 6
Generate a structured market brief
The agent must output a structured brief (JSON and a readable Markdown rendering) containing:
Summary — 2–3 sentences on what the market looks like for this role and location
Insights — a list of findings, each tagged with a confidence level and backed by evidence (the count and IDs of the
postings it is based on)
Client recommendations — a suggested job title, salary band, and the top skills to lead the job description with, each
tied to evidence
Hiring outlook — one of Favourable / Competitive / Hard to fill, with a one-line reason
Run notes — questions asked and answers given, the final search plan, postings analysed, and any assumptions made

7
STEP 7
Handle edge cases gracefully
Your agent should not crash or return garbage when faced with:
Very large result sets (more than 500 postings): implement a batching strategy so you stay within the LLM’s context
window
Niche roles or small locations with very few postings
Ambiguous or incomplete requests, including a user who gives a vague answer to a clarifying question
Missing or inconsistent salary data (hourly vs annual, mixed currencies, no salary at all)
Duplicate postings of the same job across locations or sources
Jobs API rate limits, timeouts, and transient errors
A user who stops at a pause and comes back later: the run must resume from where it stopped

Technical Requirements
Minimum bar
MUST HAVE
Built as a LangGraph StateGraph with a typed state schema (TypedDict or Pydantic); you can explain every field
At least one human-in-the-loop pause using LangGraph’s interrupt() , resumed with Command(resume=...)
(the Step 2 clarifying questions)
A checkpointer (for example MemorySaver or SqliteSaver ) so a paused run can be resumed on the same thread
Conditional edges for the agent’s routing decisions (clarify or skip, enough data or fetch again)
Tool calling: the jobs API exposed as LangChain tools ( @tool ), bound to the model, and run through a ToolNode
or equivalent
Structured output: the market brief produced through Pydantic models (for example
with_structured_output() ), not parsed from free text
Fetches real job postings from a public jobs API and runs end-to-end on at least one real role and location
A clear README with setup and run instructions
Good to have
RECOMMENDED
Parallel batch analysis using LangGraph’s Send API (map-reduce), with a reducer that merges batch results in
state
A second pause: search-plan approval, where the user can approve, edit, or reject the plan before any fetching
A third pause: the low-data checkpoint described in Step 4
Node-level retry policies for API calls, and model fallbacks ( .with_fallbacks() ) when the LLM fails or is rate-
limited
Recovery when the LLM returns malformed output
A simple CLI or minimal web UI (Streamlit, Gradio, or plain HTML) that handles the pauses properly
Configuration flags, for example --focus salary or --focus skills
Stretch goals
BONUS POINTS
Supervisor multi-agent setup: a supervisor that delegates to specialist agents (search, skills analyst, salary
analyst, report writer)
Critic pass: a reflection node that reviews the draft brief for claims not backed by postings and sends it back for
revision
Streaming progress: node-by-node progress shown to the user as the agent works (“Fetching… 142 postings
found… analysing batch 3 of 6…”)
Long-term memory: a LangGraph Store that remembers user preferences across runs (currency, default
seniority, skills to always track)
